I write programs that are maintainable, readable, and adaptable by following established principles, such as OOP, or follow industry standard practices to not only contribute to these 3, but ensure security is also followed. The CRUD project that is entwined with this one followed these established principles and thus made the adaption for this second project that much easier and significantly reduced the development time. Because of this, I can use this for later projects, school or personal, and use the functions I have created here. The update for each of those projects would me minor in comparison to creating a whole new function.

When approaching problems, I try and automate as much as possible. A specific example in the code I can give is when creating the query in the update_dashboard function, I construct the string and have the mutable parts tied to a variable so that I only have to write this once. It is tedious to create a string for each of the queries because if I want to scale, I would have to update each query separately, add new queries, etc., where I can instead create it once and simply have the part that changes mutable.
